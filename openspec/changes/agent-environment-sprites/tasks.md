## 2. Lane helper

- [ ] 2.1 Write `scripts/sprite-lane.sh` with subcommands `pool init|list`, `lane new|exec|attach|harvest|extend|rm`, and `audit [--reclaim]`, each shelling to the `sprite` CLI and the devcontainers CLI only (no hand-rolled API calls beyond `sprite api` for the network policy, labels, and any Tasks hold), and verify `task lint:shell` passes (shellcheck `--severity=error`, `shfmt -d`, bash 3.2 portable)
- [ ] 2.2 Implement `pool init`: install Docker and the devcontainers CLI in the sprite, register `dockerd` as a sprite Service, clone the default branch onto the outer host (bot PAT via git's credential helper from the exec environment, never on disk), bring the bot profile up once and tear the containers down, remove the checkout and its env-file, record the image pin in a sprite label, take the golden checkpoint, and refuse beyond the configured pool ceiling; verify with the offline test that the checkout removal precedes the checkpoint, that no file write carries the PAT, that no SSH server is installed on the outer sprite, and that the ceiling refusal fires
- [ ] 2.3 Implement `lane new` in the specified order — refuse a branch absent from the remote or a local branch ahead of the fetched remote head, refuse a stale golden pin, claim a pool sprite (local lock + lease write + readback, retry on contention, skip expired leases), restore the golden checkpoint and poll until the platform reports it complete (fail non-zero on timeout, keep the lease), set the DNS allowlist policy, clone the remote branch head onto the outer host at `/workspaces/<repo>` (PAT via the credential helper from the exec environment), run `devcontainer up` on that workspace folder with the allow-listed credentials in the command's environment so `init-env.sh` composes the env-file and post-create runs `bot-autonomy.sh apply`/`verify` authenticated, copy the Codex login into the inner container's Codex state, install the in-container SSH server (key-only), generate the per-lane keypair, install the public key, record the host key, and write the operator's SSH alias — and verify the offline test asserts this exact order and that a `verify` failure exits non-zero with the harness named
- [ ] 2.4 Implement the reconcile step every entry runs first (`devcontainer up` if the inner container is not running, which reruns `post-start.sh` and its `verify`; restart the in-container SSH server and the in-container Herdr server; refresh the SSH alias address), then `lane exec` (a detachable `sprite exec --tty` into the inner container that runs the given command), `lane attach` (`sprite sessions attach` for the lane's session, or — when the session is gone after a cold pause — a new detachable shell session in the container plus a message naming the lost session and the resume options), and `lane harvest` (which reconciles the same way before copying the report out); verify with the stubbed CLI that all three reconcile first (including the sshd restart), target the inner container, never the sprite's own shell, and that attach on a session-less lane opens a fresh session rather than failing
- [ ] 2.5 Implement the activity invariant and the command bound: every lane command runs as a detachable in-sprite exec session under an in-sprite supervisor that applies the per-command duration bound (default 2 h), registers and releases any Tasks-API hold, and stops the command with its output intact at the bound; no heartbeat, hold, or timer is owned by a process on the orchestrator's machine; verify the offline test asserts no orchestrator-side hold or timer and that killing the orchestrator-side helper records no release call
- [ ] 2.6 Implement the TTL: `lane new` records it in the lease, `lane extend` moves it, and past expiry `lane exec` refuses new commands naming `lane extend`, a running command gets the grace period (default 30 min) and is then stopped by the in-sprite supervisor with the checkout, container, and volumes intact; verify with the offline test
- [ ] 2.7 Implement `lane harvest` (reconcile, then copy the report file to the orchestrator's scratch directory and print the path) and `lane rm` in the spec's order: mark the lane closing so no new command can start, prove no lane session or command is active (refuse otherwise), refuse on a non-clean checkout — unpushed commits, modified, staged, or untracked files — without `--force`, stop the container, scrub the env-file, the Codex state, the container's `authorized_keys`, and any process environment, remove the per-lane keypair and SSH alias on the orchestrator, restore the golden checkpoint and wait for completion, release the lease, return to pool or `--destroy`; verify the closing mark, the activity refusal, the cleanliness refusal, the scrub order, and the lease release with the offline test
- [ ] 2.8 Implement `audit`: one row per pool sprite and lane (name, state, age, TTL, lease owner, issue, golden pin) from sprite labels, expired lanes and expired leases flagged, non-zero exit on any expired lane; `audit --reclaim` releases an expired lease only after confirmation and only when the platform shows no active session or running command on that sprite, restoring the golden checkpoint on reclaim; verify with the stubbed CLI's canned `sprite list` and `sprite sessions list` output
- [ ] 2.9 Write `scripts/test-sprite-lane.sh` with a stubbed `sprite` and `devcontainer` on `PATH` that record every invocation, asserting the ordering rule (claim → restore complete → policy → clone → `devcontainer up` with credentials → Codex login → SSH keys → agents), every pre-restore refusal (absent or ahead branch, stale pin, full pool, contended lease, expired lease, reclaim over an active session, retirement over an active session, non-clean retirement, expired TTL) recording no restore call, the retirement concurrency case (a `lane:exec` started after the closing mark is refused and the retirement's activity check precedes its cleanliness check), the reconcile-first rule for exec, attach, and harvest alike, the incomplete-restore case recording exactly one restore call and nothing after it, the no-orchestrator-side-hold-or-timer rule, and that neither the Sprites token (env var, token file, keyring path) nor the bot PAT appears in any written file; wire it as `task test:sprite-lane` into `task verify` (root) and verify `task verify` is green
