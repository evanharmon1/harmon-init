## 2. Lane helper

- [ ] 2.1 Write `scripts/sprite-lane.sh` with subcommands `pool init|list`, `lane new|exec|attach|harvest|extend|rm`, and `audit [--reclaim]`, each shelling to the `sprite` CLI and the devcontainers CLI only (no hand-rolled API calls beyond `sprite api` for the network policy, labels, and any Tasks hold), and verify `task lint:shell` passes (shellcheck `--severity=error`, `shfmt -d`, bash 3.2 portable)
- [ ] 2.2 Implement `pool init`: install Docker and the devcontainers CLI in the sprite, register `dockerd` as a sprite Service, pull the pinned image by bringing the bot profile up once and tearing it down, record the image pin in a sprite label, take the golden checkpoint, and refuse beyond the configured pool ceiling; verify with the offline test that no credential step precedes the golden checkpoint, that no SSH server is installed on the outer sprite, and that the ceiling refusal fires
- [ ] 2.3 Implement `lane new` in the specified order — refuse an unpushed branch, refuse a stale golden pin, claim a pool sprite (local lock + lease write + readback, retry on contention, skip expired leases), restore the golden checkpoint and poll until the platform reports it complete (fail non-zero on timeout, keep the lease), set the DNS allowlist policy, run `devcontainer up` inside the sprite with the allow-listed credentials in that command's environment so `init-env.sh` composes the env-file and post-create runs `bot-autonomy.sh apply`/`verify` authenticated, copy the Codex login into the inner container's Codex state, install the in-container SSH server and write the operator's SSH alias — and verify the offline test asserts this exact order and that a `verify` failure exits non-zero with the harness named
- [ ] 2.4 Implement the reconcile step every entry runs first (`devcontainer up` if the inner container is not running, which reruns `post-start.sh` and its `verify`; restart the in-container Herdr server; refresh the SSH alias address), then `lane exec` (a detachable `sprite exec --tty` into the inner container that runs the given command) and `lane attach` (`sprite sessions attach` for the lane's session); verify with the stubbed CLI that both reconcile first, target the inner container, and never the sprite's own shell
- [ ] 2.5 Implement the activity invariant: every lane command runs as a detachable in-sprite exec session, any Tasks-API hold is registered and released by an in-sprite supervisor wrapping the command, and no heartbeat or hold is owned by a process on the orchestrator's machine; verify the offline test asserts no orchestrator-side hold and that killing the orchestrator-side helper records no release call
- [ ] 2.6 Implement the TTL: `lane new` records it in the lease, `lane extend` moves it, and past expiry `lane exec` refuses new commands naming `lane extend` while a running command finishes and nothing is destroyed; verify with the offline test
- [ ] 2.7 Implement `lane harvest` (copy the report file to the orchestrator's scratch directory and print the path) and `lane rm` (refuse on a non-clean checkout — unpushed commits, modified, staged, or untracked files — without `--force`; stop the container; scrub the env-file, the Codex state, and any process environment; restore the golden checkpoint and wait for completion; release the lease; return to pool or `--destroy`); verify the refusal, the scrub order, and the lease release with the offline test
- [ ] 2.8 Implement `audit`: one row per pool sprite and lane (name, state, age, TTL, lease owner, issue, golden pin) from sprite labels, expired lanes and expired leases flagged, non-zero exit on any expired lane; `audit --reclaim` releases an expired lease only after confirmation and restores the golden checkpoint on reclaim; verify with the stubbed CLI's canned `sprite list` output
- [ ] 2.9 Write `scripts/test-sprite-lane.sh` with a stubbed `sprite` and `devcontainer` on `PATH` that record every invocation, asserting the ordering rule (claim → restore complete → policy → `devcontainer up` with credentials → agents), every refusal (unpushed branch, stale pin, full pool, contended lease, expired lease, incomplete restore, non-clean retirement, expired TTL), the no-orchestrator-side-hold rule, and that the Sprites token (env var, token file, keyring path) never appears in any recorded argument or written file; wire it as `task test:sprite-lane` into `task verify` (root) and verify `task verify` is green
